# 音屿-Apple TV音乐播放器安装助手 · FrpDeck 全局 UI 体系移植规范

> **2026-11-04 · 产品所有者最新设计决策 · 必须优先执行。**  
> 本文覆盖先前视觉交接文档里与 FrpDeck 全局风格不一致的布局、导航与配色要求。是给 Codex 的实际开发指令，**不是已完成的代码**。
>
> 公开仓：`songdone/songlib-tv-installer`，当前整改 PR #1。

## 0. 用户真实要求：全局复用 UI 语言，而不是复刻 FrpDeck 金色

**必须理解为：FrpDeck 的页面组织方法、栅格比例、控件风格、留白、质感、动效、导航、交互、信息密度、响应式以及购买/授权展示系统，全部作为本项目 UI 母版；重新定义适合音屿品牌的配色、图形与内容。**

- 是 **整站一套视觉系统**，不是只参考购买页面、只改首页、只换一块宣传 Banner。
- 是复用 FrpDeck **设计语言与交互规律**，而不是将 FrpDeck Logo、金色值、NAS 图、内网穿透词汇、机器码逻辑原样搬过来。
- 界面整体必须看起来属于同一个产品：登录 → 工作台 → 设备 → 安装 → 签名账户 → 应用续签 → 探索音屿 → 购买与授权 → 设置/帮助 → 弹窗/错误页。
- 主标题及宣传：**「你的音乐 自成一屿」**，这是唯一正式 Slogan。
- 不另行发明一套 Apple × MIUIX 侧边栏 UI。如果与 FrpDeck 现有模式冲突，以 **FrpDeck 实际成熟组件和交互** 优先，然后按安装助手业务调整。
- 本项目已有 Vue 3 SFC + Vite / Tailwind / DaisyUI 和 Go 签名服务。**不要把 FrpDeck 全局 JS 模板框架整套硬拷贝过来，不改签名引擎。** 使用目标项目现有技术栈提炼并实现一致的 Vue 设计系统。

## 2. 全站导航：以 FrpDeck 的 topbar + bnav 为主

不要再硬性指定「左固定 216px 侧栏 + 右工作台」，那是旧交接的错误设计预设。

**桌面：** FrpDeck 式紧凑顶栏（约 64px，随真实效果调节），左音屿 Logo/应用名、中间主导航、右侧语言/主题/帮助/公开 GitHub/账户；活跃项有柔和选中背景与滑块/下划线反馈（按实际测试选最佳方案）。

主导航建议：
- **总览**：近期设备、需要操作的事项和简洁音屿宣传
- **Apple TV**：发现、配对、连接和设备信息
- **应用与续签**：已装 IPA、有效期、更新、重签、错误恢复
- **签名账户**：Apple 小号、证书、认证状态
- **音屿播放器**：真实 TV 体验、下载、功能介绍、购买与授权
- **设置 / 帮助**：单独工具入口或次级导航

购买与授权既可以成为「音屿播放器」内的显眼二级标签，也可以做一级「购买音屿」入口；由实际信息密度选定，但**必须有可直达的独立页面路由**，不能只是一段首页横幅。

**手机：** FrpDeck 式 `bnav` 底部主导航，顶栏仅保留 Logo/标题/必要操作；主导航过多时采用 4–5 个入口 + 「更多」，保持易操作。适配 iPhone Safari / Chrome 视口与 safe-area。不要让两个导航同时拥挤显示。

**平板：** 先沿用 FrpDeck 的响应式顶部导航；能完整放下就不额外创建侧栏。全站主框架保持统一，避免设备页一套、购买页另一套。

## 3. 全局视觉方法：FrpDeck 质感，音屿品牌颜色

**继承的视觉规律：**
1. 克制的背景环境光、微透明卡片、精细边框和自然阴影。
2. 内聚式卡片组：组件不是每项一个浮夸卡片，标题、状态、操作和说明建立统一层级。
3. 按钮有主次：主按钮明显，次级朴素，危险动作使用语义化红色；杜绝随处使用金边按钮。
4. 统一圆角梯度（参考 8/10/14/18/22px）、间距梯度（4/8/12/16/20/24/32px）、版心和字体等级。
5. 运行状态必须明确：未连接/已连接/安装中/续签成功/需重新授权/失败，使用语义色 + 文本 + 图标，不能仅靠颜色。
6. 轻量状态反馈：hover、focus-visible、press、loading、toast、popover、modal、drawer、progress、empty state 都有系统性规范。
7. 支持深色/浅色/系统外观；从一个统一主题机制实现，防止页面之间主题串色。

**不继承的具体内容：**
- FrpDeck logo、金色/香槟色必须与原值一致的要求。
- 其专属 NAS 机器码、FrpDeck 三台绑定规则、活动 60 天与 NAS 授权展示逻辑。
- 其服务器监控、代理线路、隧道业务指标和对应图标。
- 任何需要额外版权授权的原图或字体文件。

### 色彩 Token 设计规范（不是锁死色值）

Codex 从 **音屿正式 Logo 原图**（仓内 `branding/` 与 `web/static/public/songlib-mark.png`）提取主色。候选需先输出光/暗色效果图给用户审核，再固定可测的最终 HEX：
- `--sl-bg`, `--sl-bg-soft`, `--sl-surface`, `--sl-surface-raised`, `--sl-border`;
- `--sl-text`, `--sl-muted`, `--sl-subtle`;
- `--sl-accent`, `--sl-accent-strong`, `--sl-accent-soft`, `--sl-accent-on`;
- `--sl-good`, `--sl-warning`, `--sl-danger`, `--sl-info`;
- `--sl-shadow`, `--sl-shadow-hover`, `--sl-radius-*`, `--sl-space-*`, `--sl-motion-*`.

推荐走**柔和中性色底 + 音屿自身品牌色点睛**。光/暗模式均应保证内容可读、按钮显著、产品截图不被底色吞没；文字对比度以 WCAG AA 为基线（一般文字 ≥4.5:1，大字 ≥3:1）。不规定必须为香槟金，也不规定必须冷蓝或纯黑。

### 设计落地的 CSS 规则

- 建立 `web/static/src/styles/tokens.css`、`shell.css`、`components.css` 和各页面局部样式（Codex 可选等价结构）。
- 将旧 `app.css` / `mobile.css` 重复、冲突的 `atv-*` 选择器合并重构，不要继续在末尾追加多层 `!important`。
- FrpDeck 的大文件是**视觉参考**，不是要直接引入 `base.css + ui.css + pages.css` 与 DaisyUI 冲突。
- 组件 API/主题变量集中，页面调用可复用的组件；在品牌换色时整个项目应同时一致生效。

## 5. 特别补齐：独立的「购买与授权」页

FrpDeck 商品卡视觉可以较高程度重用，但销售内容和业务逻辑必须完整重写。

### 页面结构（与 FrpDeck 一致的 UI 质感）

1. 页首「购买音屿播放器」/ 副说明：**安装助手免费，购买的是音屿音乐播放器的商业授权**。
2. 两张横排套餐卡：**基础版、Pro 版**。卡片内部左侧专属音乐产品配图（不要用 FrpDeck NAS 产品图），右侧版本名、实时价格、功能点及 CTA。桌面两列、移动单列；切勿为了双列牺牲文字可读性。
3. 实际可用的 **16688 商品购买链接**：从配置/经验证的公开官网购买信息获取，未配置时隐藏购买动作并给管理端诊断。价格只能从可信配置/平台获得；不许使用 FrpDeck 的 ¥8.8 / ¥18 价格冒充音屿价格。此前官网基础版 ¥6、Pro ¥18 是旧页面标价，不代表当前 16688 价格。
4. 产品版本功能对比表：以音屿正式授权后的真实区别为准，不套用 FrpDeck 线路/容器比较。
5. **购买/激活步骤**：选择版本 → 16688 下单领取兑换码 → 回到音屿播放器或官网官方入口激活（按产品当前真实流程）。
6. 关于试用、设备数、退款及换机、自动续签的 FAQ。

### 重要业务边界

- 本 FPK **不能**像 FrpDeck 一样读取 NAS Docker 机器码来激活音屿，它只是签装与版本入口。
- 本 FPK 不必请求、保存或校验音屿商业兑换码；不得加入本机「粘贴授权码立即激活」框，否则会误导用户以为签名工具能直接激活 tvOS / iOS / Mac 播放器。
- **30 天 Pro 试用**与**基础版/Pro 共用最多 6 台 iOS/Apple TV/Mac**：必须与私有音屿授权后端/官网实际接口状态一致；已激活用户继续受原权益保护，不擅自迁移旧兑换记录。Mac 版未上架时加“Mac 版推出后适用”。
- **7 天个人 Apple 账户自签有效期**独立于上述音屿 30 天试用和永久授权，FAQ 必须单独解释。
- 音屿播放器不随 FPK 打包 IPA，下载跳音屿官网独立发布。

## 6. 页面视觉制作和实施顺序

**P0：统一视觉架构。** Codex 先把 FrpDeck 完整组件风格提取成 `UI_COMPONENT_MAPPING.md`，与当前首页/添加设备/安装页/账户页/设置页逐项对照，出一个现有样式清理清单。确认音屿 logo 的颜色来源，不改业务 API。

**P1：先做全站 AppShell。** 顶部主导航、移动端底部导航、全站 token、基础按钮/卡片/表单/浮层/状态组件；执行深浅色一致性检查。避免只改一页。

**P2：逐页替换视觉。** 登录/总览/设备/安装与续签/签名账户/探索音屿/购买与授权/设置/关于。优先保证真实业务页面可用，无需同时改变后端。

**P3：视觉核查与真实功能验证。** 360/390/768/1024/1440px，浅色/深色/系统，空状态/异常/已连接/安装中/续签失败。检查 GitHub 源码入口、密码安全、原先 Go API、移动滚动、fnOS 嵌入与 16688 实际商品跳转。
