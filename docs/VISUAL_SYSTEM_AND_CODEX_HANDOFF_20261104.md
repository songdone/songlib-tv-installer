## 0. 不得变更的决策

1. **应用全称：`音屿-Apple TV音乐播放器安装助手`**。桌面端标题栏可完整展示；在窄屏导航可简写为“音屿 TV 安装助手”，但 About、Manifest、应用中心和文档沿用全称。
2. **唯一正式 Slogan：`你的音乐 自成一屿`**。视觉可双行排版成“你的音乐 / 自成一屿”，不能改成“让收藏的音乐，成为客厅主角”或“让散落的音乐，回到自己的岛屿”。
3. 官方音屿播放器与开源安装助手是**两个独立产品**。安装助手免费、允许安装其他合法 tvOS IPA，不捆绑音屿商业版 IPA。
4. 页面只承诺已验证的 **Apple TV 发现 / 配对 / tvOS IPA 签装 / 续签**功能。源码出现 iPhone/iPad 扫描代码不等于已完成 iPhone 自签；未通过端到端测试前不能在普通入口宣称可给 iPhone 安装 IPA。
5. iOS 版音屿仅作为**产品了解/下载链接**；Mac 版未正式发布前，只显示“敬请期待”，不展示假下载按钮。
6. **30 天 Pro 试用、单码至多 6 台跨 iOS/TV/Mac、16688 购买链接**必须跟随私有商业后端的真实上线状态。未生效时隐藏或采用中性说明，不得把“设计需求”当成“已上线权益”。“7 天 Apple 免费自签”与“30 天音屿商业试用”是完全不同的两条有效期。
7. GitHub 顶部主入口必须是 `https://github.com/songdone/songlib-tv-installer`。上游 ATVLoadly 的源码、作者和许可证保留在“关于 → 开源致谢”，绝不删除版权信息。
8. 应用图标从现有音屿标志图形产生：**应用图标 256×256 PNG**、**应用中心详情图 512×512 PNG**。同一图形用于页签、导航、关于、FPK 桌面入口，不再混入上游的红色三角形。
9. **保留原有 Go 服务、签名与续签内核，优先换信息架构、Vue 页面和视觉设计；不得以重做 UI 为由重新发明签名协议。**
10. 公开仓不得加入商业播放器源码、IPA、dSYM、授权私钥、商户密钥、生产数据库和非公开内测资源。AGPL 许可、上游历史、对应源码下载/构建说明必须保留。

## 1. 设计方向与避免事项

### 1.1 视觉定位

> **Apple 原生软件的秩序感 × MIUIX 风格的轻盈交互 × 音屿品牌的音乐氛围。**

- 基调：**浅色优先**、温暖中性的页面背景、细腻轻磨砂、少量金色强调、布局整洁、留白但不空洞。
- 内容优先级：**音屿是什么 → 如何在 Apple TV 安装 → 已有设备/应用怎么管理**。
- 音乐感来自**真实播放器截图、专辑封面、歌词与产品语言**，而不是大量音符装饰、假频谱、光污染。
- “高级”来源于统一栅格、文字层级、对齐、适度留白与动效节制，**不是多套玻璃特效、深色巨幅 Banner、重复按钮边框**。
- 不照搬 macOS 系统窗口的红黄绿控制点；这是运行在飞牛里的 Web 管理页面，不是假装一个 Mac App。

### 1.2 明确禁止

- 旧版：顶部窄导航 + 大块黑绿“促销横幅” + 下面突兀蓝白设备表；**不得继续以这一结构打补丁**。
- 不采用 Bootstrap 风格的蓝色主按钮、默认灰色表头、巨大空白区域和密集描边小按钮。
- 不在大面积暗底上堆金字，也不把 Logo 金色当成所有小字的常规颜色（对比度不足）。
- 不把“添加新设备”“没有连接设备”“没有数据”拆成三个占大面积的重复空状态。
- 不把“发现设备、配对、导入 IPA、账户、证书、已装 App、续签状态”全部塞首页同一长表格。
- 不加不可点击的按钮、假设备状态、假的销售链接、伪造版本号；不以 Mock 截图冒充实机验收。
- 不为了看着像精致卡片而给所有区块加框；导航、正文和分隔线也能建立层次。

## 3. 栅格、尺寸与响应式规则（可直接编码）

| 视口 | 导航 | 内容布局 | 横向内边距 | 元素间距 |
| --- | --- | --- | --- | --- |
| ≥1440px | 左固定 216px | 主区域最大 1240px；12 列网格，20px 间隔 | 36px | 24–32px |
| 1024–1439px | 左固定 200px | 主区域自适应；Hero 约 55:45 | 24px | 20–24px |
| 768–1023px | 左侧缩为 68px 图标栏 | Hero 约 50:50，流程卡整行 | 24px | 16–20px |
| 480–767px | 顶部品牌 + 可收起导航 | 一列，Hero 文案在上、截图在下 | 20px | 16px |
| ≤479px | 顶部 56px，紧凑菜单 | 一列，步骤纵向或可横滑但无页面溢出 | 16px | 12–16px |

- 顶部条 desktop 64px、mobile 56px；侧栏纵向可滚动且保留当前导航高亮。
- 主内容 `max-width: 1240px`；在超宽屏仍保持合理阅读宽度，避免表格和正文横向拉满。
- 主布局 CSS Grid / Flex，**组件自身使用 `min-width: 0`**；长设备名称、IP、App 名可省略并提供完整 tooltip。
- Hero 建议 12 列中的 6:6 或 7:5；文案与截图均垂直居中。TV 预览框使用 `aspect-ratio: 16 / 9`，`object-fit: contain`，禁止裁切文字或歌词。
- 64px/48px 主体布局不能根据截图放大到 200px 大留白。空状态总高以 220–320px 为宜，按内容变化，不预留整屏空区域。
- 手机上主按钮通栏、次按钮可并排但至少 44px 点击高度。
- 首次访问同屏至少能找到“**开始连接 Apple TV**”；不要让用户必须先滚动到几屏后才发现入口。

### 3.1 八点间距系统

`4, 8, 12, 16, 20, 24, 32, 40, 48, 64px`；不必机械只用 8 的倍数，但应通过 tokens 统一。基础页面节奏：

- 页面标题与副文本间 `8px`；标题组与下一块 `24px`。
- 一张普通卡的内边距：desktop `24px`、mobile `16px`。
- 同级卡片间 `16–20px`；不同章节间 `32–40px`。
- 表单字段间 `16px`；字段标题与控件间 `6–8px`。
- 纯视觉装饰不应挤走工具操作空间。

### 5.1 按钮体系

- **Primary（每个功能区最多一个）**：`44px` 高，深绿中性色背景、白字，Hover 深一档。例：**开始连接 Apple TV**、**开始安装**。
- **Secondary**：浅底 + 细描边，文字深色。例：**了解音屿**、**选择本地 IPA**。
- **Tertiary / Link**：无底色的文本动作。例：**查看所有设备**、**安装说明**。
- **Danger**：仅用于删除、撤销绑定并二次确认。
- 禁用态需要 tooltip/原因，不要把尚未配置的功能伪装成 disabled Button 长期展示。

### 5.2 状态规格

| 状态 | 标题/反馈 | 主操作 |
| --- | --- | --- |
| 首次打开，无 TV | “让 Apple TV 与 NAS 连接起来” + 简短配对说明 | “发现 Apple TV” |
| 正在扫描 | 进度标识与可读文字；保留手动输入 IP | “停止扫描”（只有支持才出现） |
| 未发现 TV | “暂未发现 Apple TV” + 同网段/AP 隔离/电视配对模式排查 | “重新扫描” |
| 已发现，待配对 | 设备名 + 待配对 | “开始配对” |
| 已配对，未选择 IPA | 显示设备、签名账户准备状态 | “选择 IPA” |
| 正在安装 | 上传/签名/传输/安装阶段；真实进度与日志可展开 | 可行时“取消任务”，否则没有假取消 |
| 已安装正常 | 应用名称、下次续签计划/剩余签名有效期 | “查看应用” |
| 续签失败/临近过期 | 原因 + 上次尝试 + 下一次重试（如有） | “重试续签” / “检查账户” |

状态采用 icon + label + 色彩三重区分；不可只用“绿点/红点”。

## 7. 页面详细行为与分屏验收

### 工作台

首次打开的第一屏依次出现：**固定导航 → 音屿 Hero（左文案/右真实截图）→ 快速安装引导**。剩余屏可放设备摘要和 3 个功能亮点，但不能为了填满页面重复放 Banner。

- 续签异常：顶部可显示**一条简洁风险摘要**，点击跳“应用与续签”定位异常，不刷红整屏。

- 设备筛选：已配对、可配对、全部；可扫描与手动 IP 输入。
- 每张设备卡：设备名、IP（适当脱敏）、在线/连接/配对状态、进入详情操作。
- 无设备时只有一个引导卡；扫描失败显示排查与重试，不把“没有数据”当成错误原因。

- 续签操作必须与原有后端能力绑定；系统不存在“手动取消”的接口就不渲染。

### 签名账户

- 强调“建议新注册一个仅供自签的 Apple 账户”“双重认证”“不要使用主账户”。

### 探索音屿

### 性能与可访问性

- 不使用大面积 `backdrop-filter: blur(30px)`、多个持续运行的背景动画；仅在顶栏/弹层少量使用 10–16px blur。简洁卡片使用实色与轻阴影即可。

- 交互目标 ≥44×44px，焦点可见；表单有 label，图标按钮 aria-label；警告不能只用颜色。
- 文本对比参考 WCAG AA：普通文本至少 4.5:1，大字与图形可按相应标准；金色小字若不达标则改为深色正文配金色图形。
- 图片提供 alt、width/height、懒加载（首屏主图优先加载）；不可把播放器截图压成模糊小图。
