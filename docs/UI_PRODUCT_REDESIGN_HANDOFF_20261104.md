## 0. 第一原则：这不是 ATVLoadly 换皮

应用正式名称：**音屿-Apple TV音乐播放器安装助手**。
公开仓：**https://github.com/songdone/songlib-tv-installer**。
上游：**https://github.com/bitxeno/atvloadly**，保留 Git 历史、AGPL-3.0、版权声明和对应源码分发机制。
独立私有仓：**songdone/songlib-amp-tv**，只负责商业播放器本身、授权后端、16688 订单接入、官网。
签名工具永久免费，可以导入其他合法 tvOS IPA；购买音屿不是使用工具的前置条件。绝不把音屿商业源码、IPA、dSYM、服务器秘钥、16688 商户凭据或生产数据库提交到公开仓。

改版目标是 **产品级 Apple TV 安装助手 + 原生音屿推广体验**：明确安装对象、减少首次操作门槛、展示播放器真正的价值，不再是一条深色广告横幅压在 ATVLoadly 旧首页之上。

## 2. 产品定位与正确的功能边界

- FPK 实际服务：Apple TV 发现、配对、使用独立 Apple 账户或适用证书签名、导入 tvOS IPA、安装、查看有效期、到期前尝试自动续签、故障恢复。
- 上游代码确有 iPhone/iPad 发现与 pairing file 导入路径，但 **这不能自动证明其 iOS IPA 签名、安装、自动续签完整可用**。没有覆盖实际 iPhone 的端到端测试和产品明确决定前，公开版的首页、引导与应用中心描述均不得宣称「支持 iPhone 安装」。可保留底层兼容代码，不向普通用户暴露不成熟入口。
- iOS 版音屿：**播放器产品推荐 / 进入官网了解与下载**，不是本安装助手给 iPhone 安装。
- Mac 版音屿：**尚未发布则只显示「敬请期待」**，不提供虚假下载或可点击的无效按钮。Mac 端播放器也不是本 FPK 的签名目标。
- 「一个音屿授权最多 6 台 iOS/Apple TV/Mac 任意组合」是私有商业授权系统的业务需求，**不是 Apple 个人免费签名可安装 6 台设备的承诺**。只有在授权后端和真机验证完成后才在公开首页宣称已生效。
- Apple 免费开发者账户签名通常 7 天有效；自动续签依赖网络、Apple 账户、双重认证、证书配额、NAS 运行及设备可达性，不能宣传百分百自动成功或永久免签。

## 3. 新首页信息架构（彻底重排）

### A. 顶部栏（固定统一）

左侧：音屿 Logo 图形 + 完整应用名。宽屏名称完整、窄屏适当简写为「音屿 TV 安装助手」，hover/title 可见正式名称。
右侧：语言、主题、帮助/关于、GitHub（只指向 songdone/songlib-tv-installer）。主界面不得出现 ATVLoadly 图标、隐含上游主页/捐赠跳转。
右侧图标需要 aria-label、title、focus-visible 状态、键盘可访问。顶部不堆叠过多动作。

### B. 产品首屏（首页重点，不是广告条）

建议左右双列，左侧文字与 CTA，右侧真实 Apple TV 截图（16:9）；手机端纵向堆叠。
- 产品识别：SongLib Amp · 音屿 / Apple TV 私人音乐播放器。
- 主标题：**你的音乐 自成一屿**（用户亲自确认的唯一正式 Slogan，空格保留；排版可视觉断行但不更改文字）。
- 正文建议：**把 NAS 里的音乐直接带到电视上。音屿连接 Plex、飞牛音乐、Emby、极音乐 / Navidrome / Subsonic 与 WebDAV 等自建曲库，在 Apple TV 上呈现同步歌词、专辑封面和沉浸式播放体验。无需把自己的音乐交给第三方托管。**（仅展示已在正式发布版验证的服务类型与特性）
- 一级按钮：**下载 Apple TV 版**（官网官方版本入口）。
- 二级按钮：**了解音屿**；**领取 30 天 Pro 体验**（只有私有授权后端新试用规则实际生效时显示）。
- 购买基础版 / Pro：放在独立的清晰购买模块或次级 CTA，只有从公开配置接口拿到经过验证的 16688/官网购买地址时展示；无购买地址时隐藏，**不要展示「购买通道尚未配置」给普通用户**。
- 右侧轮播：使用音屿官网**已公开的** TV 应用截图（首页、正在播放/同步歌词、歌单）。不要用生成的假 UI 冒充真实播放器。可把公开的营销图复制到安装助手公开仓的 marketing/ 中，保留来源说明；不包括商业代码与 IPA。
- 该 Slogan 必须统一同步：公开仓首页 / 关于页 / README / FPK 应用中心描述与宣传截图，以及私有仓官网首屏 / 其它产品文案。私有仓更改应单独提交且不得因此直接部署生产站点。
- 商品卖点以 3–4 个短标签或小卡呈现：**NAS 多源音乐库、Apple TV 大屏歌词、原格式音乐播放、Pro 多库合并**。付费特性必须标注 Pro。

### C. 首次使用流程（核心可操作区域）

把当前又窄又大的「添加新设备」单独条目和空白表格重做为自然的 3 步向导：
1. **发现 Apple TV**：同局域网扫描和手动输入 IP；发现不到时提供准确排查与网络隔离提示。
2. **连接并配对**：指引电视端进入「设置 → 遥控器与设备 → 遥控器 App 与设备」，展示配对状态和真实失败信息。
3. **下载 IPA 并安装**：从官网下载到本地，再选择 IPA 导入签名。不会将 IPA 打进 FPK。首次完成后说明续签设置。

状态需实时显示「未发现 / 待配对 / 已连接 / 安装中 / 已安装 / 续签异常」。按钮和步骤不能仅做展示，必须绑定原有可工作的 API。
没有设备时优先显示此流程，**不展示一大片空表格**；连接成功后展示已连接设备卡、已安装 App 和到期时间。
应用列表在少量设备时优先使用轻量行卡片，较多时再用表格；保留排序、安装、更新、续签、错误提示等核心能力。

### D. 音屿功能介绍（让用户知道值得安装什么）

可设置「为什么用音屿听 NAS 音乐」模块，以 3–4 个视觉层次清晰的条目说明：
- **直接连接自建媒体库**：Plex、飞牛音乐、Emby、Navidrome/Subsonic、WebDAV 等已验证来源。
- **为 Apple TV 大屏而生**：正在播放视图、专辑封面、歌词与遥控器操作。
- **家庭音乐库聚合**：多音乐源、聚合与跨库浏览等 Pro 功能清晰标注。
- **一套授权，多端使用**：只在 6 台跨端授权真实上线且完成验证后出现；否则写「了解各版本授权」并链接官网。
音屿商业介绍和安装功能同时重要，但**绝不能让未购买用户无法执行免费签装**。

### E. 安全、常见问题和页脚

简短展示「建议单独申请 Apple 账户」「免费签名约 7 天」「续签依赖设备在线」「不要把账户密码提供给他人」；更完整的 FAQ 另行折叠/独立页。
底部显示 app 版本、公开源码地址、AGPL-3.0、上游 ATVLoadly 致谢与风险说明；上游应明确是技术来源，而不是本项目的官方维护仓。

## 4. 视觉规范

品牌基线为音屿既有 Logo 和**已发布的音乐播放器截图**。绝不重新设计一个莫名其妙的 App 图形。
- 应用图标：**256×256 PNG**；应用中心详情页：**512×512 PNG**。统一采用同一个音屿 Logo 图形；图标边缘、背景、圆角按飞牛实机显示验证。
- 浏览器 favicon / Apple Touch Icon / 头部品牌 / 关于弹窗 / FPK 桌面入口应使用统一素材，不能混用上游红色三角。
- 视觉关键词：**浅色、克制、通透、精致亚克力/磨砂质感、留白、清晰层级**。音屿已有深色/金色播放器视觉可以作为局部品牌色，但不能让整页只剩一整块墨绿/黑色宣传海报，和下面默认蓝白工具拼接。
- 主背景中性偏暖白，主体卡片白色/轻透明，微弱阴影，细致边框；强调色从现有音屿 Logo 提取。禁用大面积杂色、过度渐变、大量描边小按钮与堆叠的 Bootstrap 风格。
- 优先定义 CSS tokens 统一主题，不在每个 Vue 组件里反复硬编码不同灰色/金色；支持浅色、深色、系统主题，明确文字对比度。
- 重要数字/设备状态比无意义的装饰更显眼；适当 150–220ms hover transition，遵循 prefers-reduced-motion。
- 适配 360/390/768/1024/1440px；不产生横向滚动、不截断按钮、不让顶部导航覆盖下拉菜单。
- 页面要「初次访问有明确目标、设备未连接有操作、连接后有状态」，不是靠堆空白营造高级感。

## 6. 业务状态与外链规范

- 建立单点公开产品配置来源（可在公开仓内提供安全默认值，或请求官网公开配置）。仅接受 https、已配置的官方域名与经过确认的 16688 商品链接。
- 下载是「跳转官网获取最新版 IPA」，不是在 FPK 静态文件夹藏入 IPA；用户从官网得到的版本信息必须与官网一致，校验 SHA-256。
- 30 天 Pro 试用、6 台授权及 16688 购买渠道以**服务端真实实施结果**驱动；链接不存在时不渲染虚假功能。
- Apple 签名到期和音屿商业授权到期是**两条独立时间轴**，不能把音屿 30 天试用和免费开发者签名 7 天混淆。
- 官网与 FPK 的购买/试用文案统一；「Mac 版即将推出」无下载按钮。
- FPK 本身免费，通用 tvOS IPA 安装不受音屿购买状态限制。

## 7. 设计与开发流程（不允许跳步）

**P0：品牌和能力边界**
1. 修复所有可见的上游 favicon/Logo/GitHub/应用名称残留；保留合法署名。
2. 核查 iPhone/iPad 实际签装能力；在未完成端到端验证前，首页对外只展示 Apple TV。
3. 清理 README 首页与源代码入口，确保私有仓机密没有进入公开历史。

**P1：真实首页重构**
1. 输出浅色/深色首页原型：空设备、已连接、有安装中任务、续签异常四种真实状态。
2. 将官网 TV 截图和产品能力整理为可维护资源模块，统一 CTA 的优先级。
3. 编码落地，复用现有 Go API，不新造签名核心、不破坏真实配对与续签。
4. 测试登录与首次引导，检查自动更新/源跟踪、证书、设置、语言、主题仍可达。

**P2：发布和商业衔接**
1. 验证官网新试用和购买链接已真实可用后才在首页打开相关按钮。
2. 自测 x86_64、ARM64 Docker 构建，生成平台通用 FPK（是否成功需以实际测试证据为准）。
3. 在 fnOS 和 Apple TV 真机做安装、配对、签名、7 天续签观察及失败路径测试，形成版本化验收证据。
4. 实际通过后更新 README、CHANGELOG、应用中心描述及应用截图，再交由所有者决定上架提交。
